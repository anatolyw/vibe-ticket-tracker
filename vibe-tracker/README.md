# Vibe Tracker

> Local ticket tracking for vibe coders — a CLI + Express API with MCP support for AI-driven development.

Vibe Tracker is a lightweight, file-based ticket management system designed for vibe coding workflows. It provides a CLI for managing tickets and a REST API with MCP (Model Context Protocol) support for seamless integration with AI agents like OpenCode.

## Features

- **CLI-first** — Initialize and manage tickets from the terminal
- **File-based storage** — Tickets stored as Markdown files with YAML frontmatter
- **REST API** — Full CRUD via Express server
- **MCP support** — Expose tickets to AI agents through MCP tools and resources
- **Beautiful UI** — Angular 19 + Tailwind CSS 4 single-page application
- **Zero dependencies for tracking** — No database required

## Installation

```bash
npm install -g vibe-tracker
# or
npx vibe-tracker
```

## Quick Start

```bash
# 1. Navigate to your project
cd my-project

# 2. Initialize Vibe Tracker
vibe-tracker init

# 3. Start the server
vibe-tracker start

# 4. Open in your browser
# Server runs at http://localhost:61000
```

After running `init`, Vibe Tracker creates:
- `vibe-tracker.jsonc` — Configuration file
- `opencode.jsonc` — MCP server registration (for OpenCode)
- `.opencode/skills/vibe-tracker.md` — Agent skill rules
- `VIBE-TRACKER-AGENTS.md` — Agent behavioral instructions

## Configuration

`vibe-tracker.jsonc` (generated by `init`):

```jsonc
{
  "VIBE_TRACKER_PORT": 61000, // WARNING: If you change this port, update your MCP server configuration (e.g., opencode.jsonc) to match
  "VIBE_TRACKER_DOC_ROOT": ".vibe-tracker",
  "VIBE_TRACKER_TICKET_PREFIX": "issue",
  "VIBE_TRACKER_TICKET_TYPE_OPTIONS": ["issue","feat","bug"],
  "VIBE_TRACKER_TICKET_NUM_PATTERN": "XXXXX",
  "VIBE_TRACKER_TICKET_SUFFIX_LENGTH": 80
}
```

The config uses [JSONC](https://jsonc.dev/) format — comments are supported. The server looks for `.jsonc` first, then falls back to `.json`.

### Ticket Format

Tickets are stored as Markdown files with YAML frontmatter in `.vibe-tracker/`:

```markdown
---
id: "issue-00001"
title: "Add login page"
type: "feat"
status: "open"
created: "2025-01-15T10:30:00Z"
updated: "2025-01-15T10:30:00Z"
---

# Add login page

## Description
...
```

Filename: `issue-00001-add-login-page.md`

## CLI Commands

```bash
# Initialize Vibe Tracker in the current project
vibe-tracker init

# Initialize with a custom port
vibe-tracker init --port 61001

# Start the server
vibe-tracker start

# Start with a custom port
vibe-tracker start --port 61001

# Start in development mode (no child process)
vibe-tracker start --dev

# Show help
vibe-tracker --help
```

## Default Ticket Types

- **issue** — General task, request, or problem
- **feat** — New feature or enhancement
- **bug** — Fixing an existing bug

Customize in `vibe-tracker.jsonc` under `VIBE_TRACKER_TICKET_TYPE_OPTIONS`.

### Query Parameters (list)

- `status`: `open` | `closed`
- `type` (dynamic, example): `issue` | `feat` | `bug`
- `search`: text search
- `sort`: `created` | `updated` | `title`
- `order`: `asc` | `desc`
- `limit`: number (default 50)
- `offset`: number (default 0)

## MCP Endpoints

Access AI tools at `http://localhost:61000/mcp`:

**Tools:** `vibe_tracker_create_ticket`, `vibe_tracker_update_ticket`, `vibe_tracker_delete_ticket`, `vibe_tracker_list_tickets`, `vibe_tracker_get_ticket`

**Resources:** `vibe://tickets/{id}`, `vibe://tickets/{id}/raw`, `vibe://tickets/{id}/metadata`, `vibe://tickets/`, `vibe://config`

## Development

### Build from Source

```bash
# Install dependencies
cd backend && npm install && cd ../frontend && npm install && cd ..

# Build server and UI
npm run build
```

### Running Locally

```bash
# Build everything, then start the server
mkdir -p dist-server
cp -r backend/dist/* dist-server/ 
node dist-server/cli.js --help
node dist-server/cli.js start --port 61001
```

### Development Workflow

```bash
# Watch Angular changes
cd frontend && npx ng build --configuration production --watch

# Watch TypeScript server changes
cd backend && npx tsc --project tsconfig.server.json --watch

# Start the server (after building)
mkdir -p dist-server 
cp -r backend/dist/* dist-server/ 
node dist-server/cli.js start --port 61001 --dev
```

### Running E2E Tests

The project has E2E tests for both the API (backend) and the UI (frontend).

```bash
# Backend E2E tests are self-contained — they build + start their own server on port 61001
cd backend && npx playwright test

# Frontend E2E tests require the server running on port 61000
# 1. Build and start the server (from $PROJ/vibe-tracker dir)
npm run build 
mkdir -p dist-server 
cp -r backend/dist/* dist-server/
node dist-server/cli.js start --port 61000 --dev

# 2. Run UI E2E tests
cd frontend && npx playwright test
```
